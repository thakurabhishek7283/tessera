# Internationalisation

Each plugin ships English strings. A host can translate or reword anything without touching the plugin.

```ts
createTessera({
  appId: 'my-app',
  locale: 'de',
  messages: {
    de: { 'hello.reset': 'Zurücksetzen' },
    'de-CH': { 'hello.reset': 'Zrüggsetze' },
  },
  features: { hello: { enabled: true } },
}, opts);
```

## Lookup order

For the locale `de-CH`, a key is looked up in this order and the first hit wins:

1. `messages['de-CH']` from the host
2. `messages['de']` from the host
3. the plugin catalogs for `de-CH`
4. the plugin catalogs for `de`
5. the plugin catalogs for `en`
6. the key itself

Between plugin catalogs, the one registered first wins, so a plugin cannot silently override another's strings.

## Parameters and plurals

`{name}` placeholders are replaced from the parameters. When `params.count` is a number, the plural form chosen by `Intl.PluralRules` is tried first (`key.zero`, `key.one`, `key.two`, `key.few`, `key.many`, `key.other`):

```ts
i18n.addCatalog({ en: { 'cards.one': '{count} card', 'cards.other': '{count} cards' } });
i18n.t('cards', { count: 3 }); // "3 cards"
```

## Dates

`i18n.formatDate(date, options?)` and `i18n.formatRelative(date)` use `Intl` with the current locale (`"3 hours ago"`).

## Changing language at runtime

```ts
instance.setLocale('de'); // emits tessera:locale-changed; elements re-render
```

In React, `useTranslate()` returns `{ t, locale }` and re-renders on change.
